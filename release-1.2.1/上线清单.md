## 三、CurseForge 步骤（三份文件的分工）

CF 的结构是「一个项目 + 一份主页 + 每个文件一份更新说明」，所以正好三份：

1. **主页（Description）** —— 见下方「主页用哪一份」。讲这个模组是干什么的、按钮在哪、追加包怎么过滤、装哪个 jar、前置、注意事项。Fabric 和 Forge 两个文件共用这一份。
2. **Fabric 文件的 Changelog** —— 上传 `mtr_no_original_trains-fabric-1.2.1.jar` 时贴 `CF-版本介绍-Fabric.txt`。
3. **Forge 文件的 Changelog** —— 上传 `mtr_no_original_trains-forge-1.2.1.jar` 时贴 `CF-版本介绍-Forge.txt`。

上传单个文件的步骤：

1. 项目 → Upload File，选 `jars/` 里对应加载器那个 jar。
2. Display Name / Version 按上表填。**Release type 选 Release**，不要留 Beta。
3. Game Version 勾 `1.20.1`，Loader 勾对应加载器。
4. Changelog 框贴对应那份 `CF-版本介绍-*.txt`。
5. Relations 里把 MTR、FerriteCore、ModernFix 都设成 Required Dependency。

两份 `CF-版本介绍` 的差别只有三处：抬头（Fabric / Forge、文件名、加载器版本）、Forge 多一段 `FIXED`（原始键名那个 bug 只有 Forge 有）、安装段里的前置与已知可用版本。

### 主页用哪一份

CurseForge 的 Description 编辑器有两种模式：**WYSIWYG**（默认）和 **Markdown**（在编辑器右上角切换）。主页有两份内容相同的文件，按当前模式二选一：

| 编辑器模式 | 贴哪份 | 效果 |
|---|---|---|
| **Markdown** | `CF-主页介绍.md` | 标题、表格、引用块、分隔线全部正常渲染，版式好看 |
| **WYSIWYG**（默认） | `CF-主页介绍-纯文本.txt` | 无 Markdown 记号，靠空行和全大写小标题分段，粘进去就是最终效果 |

**推荐切到 Markdown 再贴 `.md`**——WYSIWYG 模式下贴 `.md` 会把 `#`、`**`、`|` 原样显示出来。

### Changelog 框没有 Markdown 模式

主页可以切 Markdown，但上传文件时那个 **Changelog 框不渲染 Markdown**：`**粗体**` 会原样显示成星号，表格会变成 `|---|---|`。所以 `CF-版本介绍-Fabric.txt` / `-Forge.txt` 仍是无 Markdown 的纯文本，靠空行和短横线分段，直接整段粘贴。

### 历史版本（1.2.0 / 1.1.0 / 1.0.0）

老版本各有一对同规格的版本介绍，放在项目 `release-archive/` 和桌面「1.2.1 上线文案\历史版本\」里：

| 文件 | 用在哪 |
|---|---|
| `CF-版本介绍-1.2.0-Fabric.txt` / `-Forge.txt` | CF 上 1.2.0 两个文件的 Changelog 框 |
| `CF-版本介绍-1.1.0-Fabric.txt` / `-Forge.txt` | CF 上 1.1.0 两个文件的 Changelog 框 |
| `CF-版本介绍-1.0.0-Fabric.txt` / `-Forge.txt` | CF 上 1.0.0 两个文件的 Changelog 框 |

同样是纯文本、无星号无表格，可直接整段粘贴覆盖旧内容。三处历史事实已按当时实际产物写死：1.0.0 的 Forge 构建锁死在 MTR 4.0.5（4.0.6+/4.1.x 拒绝加载）；1.1.0 才解除锁定并把 FerriteCore / ModernFix 变成硬前置；1.2.0 才有主菜单选择器，文件名也是从 1.2.0 起才带 `-fabric` / `-forge`。
