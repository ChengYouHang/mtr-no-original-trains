No Original Trains 1.1.0 — Forge
File: mtr_no_original_trains-1.1.0.jar
Minecraft 1.20.1 · Forge 47.x


ABOUT THIS VERSION

1.1.0 makes the mod independent of a specific MTR version. The 1.0.0 Forge build refused to load with MTR 4.0.6+ or 4.1.x; this build accepts any MTR 4.x. Instead of a frozen list of IDs taken from MTR 4.0.5, it reads MTR's own vehicle manifest at runtime and works out which trains are MTR's built-ins by itself.

Read this one before updating: 1.1.0 adds two hard dependencies that the game will refuse to start without, and they must be the Forge builds.


WHAT CHANGED

- No more hard-coded train list. At startup the mod scans every installed resource pack and finds the manifest MTR itself ships — the one containing all of MTR's own vehicle IDs. Whatever trains that manifest declares are the ones that get removed.
- No longer pinned to MTR 4.0.5. The 1.0.0 Forge build refused to load with MTR 4.0.6+ or 4.1.x; this build accepts any MTR 4.x.
- MTR 4.x updates are picked up automatically. When MTR adds, renames or removes a built-in train in a future 4.x release, the mod follows along. No update to this mod, no config edit, no reinstall.
- Addon packs stay 100% safe. Identification uses two independent checks — ID-set match plus pack-name match. A pack that only looks like MTR is never mistaken for it, and any vehicle claimed by another pack is still never blocked.
- Fallback kept. If MTR's own manifest cannot be identified for any reason, the mod falls back to the original 4.0.5 blacklist rather than risking your addons.
- Same behaviour as the Fabric build, on Forge 47.x.


BREAKING CHANGE — TWO NEW REQUIRED DEPENDENCIES

From 1.1.0 on, this mod requires FerriteCore and ModernFix, and will refuse to load without them.

- FerriteCore (Forge) — deduplicates block and item model data in memory.
- ModernFix (Forge) — cuts startup time and memory use.

Why they are mandatory: MTR addon packs routinely ship very large textures. Combined with decorative mods, the block atlas can grow past the point where Minecraft can build its mipmaps, which hangs the game on startup or on world load. These two mods address that directly; without them this mod's own purpose — running high-quality addon trains on modest hardware — is not achievable.

If they are missing, the game stops at the loading screen with a "missing mandatory dependencies" error naming ferritecore and modernfix. It never reaches the main menu.


INSTALL

- Install the Forge builds of FerriteCore and ModernFix first, then replace the jar. Your config file is not touched.
- Drop mtr_no_original_trains-1.1.0.jar into mods/.
- Requires Minecraft Transit Railway 4.0.0 or newer (any 4.x), plus FerriteCore (Forge) and ModernFix (Forge).
- Client-side only. Servers do not need it. Do not install this jar on Fabric.
- Updating from 1.0.0: delete the old jar rather than keeping both, they share a mod ID.
- Known good on Forge 47.4.26. Any Forge 47.x on 1.20.1 should work.
- On 1.1.0 the Fabric and Forge builds share the same file name, mtr_no_original_trains-1.1.0.jar. Whichever one you downloaded is the one for this loader; the -fabric / -forge suffix only starts with 1.2.0.
